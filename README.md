# Kintzio

Standalone Konstantinos Kintzios chatbot with a Gemini embedding index, Simasia-style widget, and a single-service Render deployment.

## Stack

| Piece | Technology |
|-------|------------|
| Web + widget | Vite + React (`apps/web`) |
| API + production web host | Fastify (`apps/api`) on Render |
| Vectors + metadata | PGlite + pgvector on a persistent Render disk |
| Files | Persistent Render disk |
| LLM | Gemini |

Interfaces live in `@kintzio/core` (`VectorStore`, `ObjectStore`, `Embedder`, `ChatModel`).

## Quick start

```bash
cd kintzio
cp .env.example .env
# set GEMINI_API_KEY=...

npm install
npm run db:migrate
npm run seed
npm run dev
```

- Web: http://localhost:5173  
- API: http://localhost:8787  

1. Enter a username (stored in `localStorage`)  
2. Create a bot → add PDFs/URLs → **Adaptive** or **Full** rebuild  
3. **Test in platform** or open **Embed demo**

## Preconfigured bot

`npm run seed` safely creates or updates the Konstantinos Kintzios bot and
reconciles its knowledge sources to the seven configured page URLs. It is
repeatable: source IDs are deterministic, duplicate URLs are removed, every
source remains in `page` scrape mode, and chat citations stay disabled.

```bash
npm run seed          # configure only
npm run seed:build    # configure and run a full knowledge build
npm run seed:verify   # full build plus one Greek chat smoke test
```

The stable bot ID is `7c1e1708-93eb-5e52-8f3c-e8fbf4f92df4`.

### Optional: Docker Postgres

```bash
docker compose up -d
# in .env:
# DATABASE_URL=postgresql://kintzio:kintzio@127.0.0.1:5433/kintzio
npm run db:migrate
```

Default `DATABASE_URL=pglite:./data/pglite` needs no Docker.

## Deploy to Render

The included `render.yaml` creates one Docker web service and a 1 GB persistent
disk. Fastify serves both the built React app and the API, so Netlify and
Supabase are not required.

Production uses lightweight static HTML ingestion for the seven configured
WordPress pages. Chromium is intentionally disabled to keep the 512 MB Starter
instance and Docker image small.

1. Push this repository to GitHub.
2. In Render, choose **New → Blueprint** and select the repository.
3. Enter `GEMINI_API_KEY` when Render requests the unsynced secret.
4. Deploy. The first boot seeds and builds the 7-source bot once, then writes a
   versioned marker to the persistent disk.
5. Open the Render service URL. `/health` is the health endpoint.

`ADMIN_API_KEY` is generated by Render and protects `/auth/*` and `/bots/*` in
production. Public config, chat, embed, static assets, and the chatbot page
remain accessible. Keep the generated key secret.

The persistent disk is required. Without it, the PGlite database, embeddings,
and uploaded avatar would be lost on redeploy or restart.

## Env

See [`.env.example`](.env.example). The browser never sees `GEMINI_API_KEY`.

Defaults that work with current Gemini APIs:

- `GEMINI_EMBED_MODEL=gemini-embedding-001` (768 dims)
- `GEMINI_CHAT_MODEL=gemini-flash-lite-latest`
